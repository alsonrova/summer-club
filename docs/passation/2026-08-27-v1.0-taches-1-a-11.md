## Pièges de l'environnement

- **Le conteneur PostgreSQL s'arrête tout seul** (instabilité Docker Desktop connue). Symptôme : une vingtaine de tests en échec et une trentaine ignorés, sur du code pourtant vert. Réflexe : `docker compose -f docker/compose.dev.yml up -d` avant de suspecter le code.
- **`next dev` ne sert rien sur cette machine** : il démarre, n'émet aucun log, ne répond jamais. Playwright vise `npm run start` ; un `npm run build` doit donc précéder.
- **`npm install` prend 10 à 20 minutes.** Windows Defender analysant `node_modules` est le suspect principal — une exclusion sur `D:\Projet` réglerait probablement le problème.
- **Ne jamais lancer deux `npm install` en parallèle** : cela a corrompu `node_modules` deux fois.
- **Prisma épinglé en 6.19.3** ; la v7 supprime `url = env("DATABASE_URL")` dans le schéma.
- **zod est en version 4** : `_def.type`, et non `_def.typeName` comme en v3.
- `prisma migrate dev` échoue sans terminal interactif dès qu'il doit avertir. Contournement : `prisma migrate diff` puis `prisma migrate deploy`.
- Node exécute le TypeScript nativement (`node --experimental-strip-types`) : `tsx` est inutile.
- Configuration du serveur de prévisualisation : `D:\Projet\.claude\launch.json`, entrée `summerclub`.

## Convention de sécurité, valable pour toutes les tâches d'administration

Un layout ne suffit pas : il n'est pas ré-exécuté à chaque navigation, ne s'exécute pas sur une route inexistante, et ne protège ni les Server Actions ni les Route Handlers. **Toute page, toute action serveur et tout Route Handler sous `/admin` doit appeler `requireAdmin()` lui-même.**
